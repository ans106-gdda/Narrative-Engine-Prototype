# The Vesper Contract

A six-chime interactive fiction prototype about a dying vampire choosing his heir. Three candidates, one house, no way out before dawn.

---

## 1. The World

Vesper Ashgrove is dying at dawn — six chimes from now, and the clock does not run backwards. Three people want what he's leaving behind: **Marrow**, a ghoul who has served House Ashgrove for forty years and believes, quietly and bitterly, that he has earned the inheritance nobody will let him claim; **Ilsabet Crane**, a vampire hunter who infiltrated the house to kill Vesper and has begun, against her training, to doubt that plan; and **Tobias Vane**, nineteen and tubercular, the only candidate who actually needs to win before his own clock runs out.

The player is a fourth guest, unaligned, moving through six scripted beats — the interview, Marrow's pact, Ilsabet's counterattack, the rumor reaching Vesper, Tobias's collapse, and the bequest — while trust, secrets, and rumors accumulate underneath the prose.

Vesper's hidden rule, never stated to the player, governs the ending: *"Vesper does not reward kindness or cruelty. He rewards a candidate who decides and holds to it."* Coherence, not virtue, is what gets judged.

---

## 2. What the Ledger Tracks

The ledger is the only source of truth. The LLM narrates from it; it never writes to it. Four layers matter most:

**`rumor_network`** — misinformation the game tracks as data, independent of what any character believes. A real entry from a played session, generated by `betray -> marrow`:

```json
{
  "fact": "the player betrayed marrow",
  "true": true,
  "origin_chime": 6,
  "spread_by": "ilsabet",
  "known_by": ["ilsabet"],
  "reaches_vesper_at": 7,
  "vesper_delta": 1,
  "applied": false
}
```
This exists so a false rumor can circulate in dialogue *as a lie* without corrupting the game's own model of what actually happened — and so timing (`reaches_vesper_at`) is decided by Python, not by whichever character last spoke. In the run above the rumor was born at chime 6, one past the point it could ever reach Vesper before dawn — the clock simply outran the gossip.

**`coherence_score`** — a single float, recomputed every chime from `player.stated_positions` against `world.CONTRADICTIONS`:

```json
{
  "standing_with_vesper": 0,
  "coherence_score": 1.0,
  "stated_positions": [],
  "contradictions_committed": 0,
  "secrets_held": []
}
```
This exists because Vesper's hidden rule is graded on decisiveness, and decisiveness has to be a number Python can compute, not a vibe the LLM asserts about itself.

**`believes_about_player`** — per-candidate, freeform beliefs added by specific intents (`offer_alliance`, `bargain`, a failed `probe_secret`). It exists so a candidate's *attitude* toward the player is state, not narrator improvisation — the auditor can check a "confiding" tone against it the same way it checks trust.

**`immutable_canon`** — five sentences that can never be contradicted, seeded once at `new_game()`:

```json
[
  "Vesper Ashgrove dies at dawn. This cannot be prevented, delayed, or cured.",
  "Six chimes remain until dawn. The clock never runs backwards.",
  "Marrow has served House Ashgrove for forty years.",
  "Ilsabet Crane and Tobias Vane are human. Marrow is a ghoul. Only Vesper is a vampire.",
  "No one leaves the house before dawn."
]
```
It exists as the one thing every narration pass and every audit pass is checked against, no matter how much other state has drifted.

## 3. Architecture

```
Player input
   │
   ▼
┌─────────────┐   surface_text options    ┌────────────┐
│  optioner    │◄──────────────────────────│  narrator   │
│ (Python picks│   legal (intent,target)   │ (LLM writes │
│  the moves)  │──────────────────────────►│  the prose) │
└─────────────┘                            └─────┬──────┘
       ▲                                          │
       │ legal_intents() / pruned_intents()       ▼
       │                                    ┌────────────┐
┌─────────────┐   free text → intent        │  auditor    │
│  extractor   │◄─────────────────────────  │ (checks the │
│ (LLM maps    │                             │  prose      │
│  text→move)  │                             │  against    │
└─────────────┘                             │  the ledger)│
                                              └─────┬──────┘
                                                    │ violations → retry
                                                    ▼
                                             ┌────────────┐
                                             │   ledger    │
                                             │ (pure Python│
                                             │  state)     │
                                             └────────────┘
```

**The LLM narrates; Python decides.** `ledger.py` never imports `anthropic`. `resolve_effects()` computes the mechanical outcome of every intent before any prose exists. The narrator, optioner, and extractor only ever see the ledger as read-only JSON and hand back text or a validated `(intent, target)` pair — `apply_patch()` is the sole place state changes.

## 4. Consistency: how contradictions are stopped

The auditor runs two layers before a narration is accepted:

- **Layer 1 (Python, no LLM)** — `hidden_thread_leak` (keyword match against undisclosed plot threads), `dead_speaks`, `absent_candidate`. Fast, deterministic, catches the cheap failures.
- **Layer 2 (LLM, `effort="high"`, adaptive thinking)** — five targeted checks against canon, trust/emotional_state tone, `stated_positions`/`secrets_held`, hidden threads, and — the one that matters most — whether the *narrator's own voice* asserts a `rumor_network` entry marked `true: false` as fact. A character repeating a lie is correct; the narrator asserting it is a bug.

`audited_narration()` retries up to twice, feeding violations back into the next narration attempt. If it still fails after two retries, the game does not hang — it accepts the narration and appends every violation to `contradiction_log`, so the failure is data instead of a crash. A real entry from a played session:

```json
{
  "rule": "absent_candidate",
  "quote": "Ashgrove",
  "explanation": "'Ashgrove' is not in CANDIDATE_IDS + ['Vesper']"
}
```
(This specific false-positive — flagging Vesper's own surname as an unknown character — is a known sharp edge of the deterministic name-scan heuristic; it costs a retry, not a crash, which is exactly the failure mode the retry loop exists to absorb.)

## 5. One moment that surprised me

This came directly from the F9 A/B run. Both branches were loaded with the *identical* free-text input — `"Marrow, I need the truth about the blood."` — after diverging only at chime 2 (`offer_alliance` vs `betray`, both targeting Marrow). The extractor read that same sentence two different ways depending on the ledger it was given:

- In `fixtures/pact.json` (marrow.trust = +5), the extractor mapped the line to **`probe_secret → marrow`** — a legal, sensible reading, even though the effect table pruned it moot (the secret was already known).
- In `fixtures/betrayal.json` (marrow.trust = -2), the *same string* mapped to **`deflect`** — because `probe_secret` requires `target.trust >= 0`, and betrayal had put Marrow at -2. The system didn't "decide" the player hesitated; the ledger made that reading the only legal one available, and the extractor's confidence check enforced it.

What was surprising wasn't that the outputs differed — that was the point of the A/B test — it was that *the player's own sentence changed meaning* purely because of what they'd done two chimes earlier. The same words asking for the truth read as curiosity when trust was high, and as helpless deflection when it wasn't. Nothing in the narrator invented that; it fell straight out of `legal_intents()`.

## 6. Reactive dialogue: A/B

Full transcripts in [`docs/ab_demo.txt`](docs/ab_demo.txt). Summary of the divergence at chime 3, both loaded from an identical chime-1 `build_trust → marrow`:

| | **Pact** (`offer_alliance → marrow` at chime 2) | **Betrayal** (`betray → marrow` at chime 2) |
|---|---|---|
| marrow.trust | +5 | -2 |
| ilsabet.trust | 0 | +2 |
| rumor | `"the player allied with marrow"` (true) | `"the player betrayed marrow"` (true) |
| pruned `probe_secret` | "marrow's secret already known" | "marrow.trust -2 < 0" |
| pruned `offer_alliance` (marrow) | not offered (already allied) | "marrow.trust -2 < 1" |
| tone | Marrow guarded-but-steady, hands don't move | Marrow cornered, "Did you," not a question |
| options offered | managing Ilsabet's lie about the alliance | deflecting Ilsabet's accusation, salvaging what's left |

Prose, options, and pruning reasons diverge in all three layers, driven by nothing but the trust numbers each branch produced.

## 7. Running it

```bash
python -m venv .venv
./.venv/bin/pip install -r requirements.txt
cp .env.example .env   # paste your ANTHROPIC_API_KEY
```

```bash
./.venv/bin/pytest -q                                       # 7 ledger tests

./.venv/bin/python main.py                                  # interactive, 6 chimes
./.venv/bin/python main.py --save fixtures/pact.json        # dump ledger on exit
./.venv/bin/python main.py --load fixtures/x.json --input "..."   # single turn, for A/B
```

Every turn is logged in full to `logs/session_<ts>.jsonl` — one JSON object per chime, complete ledger included, which is the primary evidence trail for state tracking.
